# 微信小程序前端功能总表与遗漏核对

日期：2026-09-05。用途：在绘制页面之前确定功能范围、入口、状态和验收标准。

本文依据现有前端设计、后端设计与本次读取的三种 Agent 官方目录编制。所有编号均为本次新增的需求追踪编号，不是 API 名称、字段、路由或既有项目标识。所有“补齐”内容是本次前端设计要求，不代表用户环境已经实现。本文不冻结依赖版本或外部协议 schema。

“全部”在本文中的边界是：已读取文档中的前端需求、所列原生目录入口和完整使用流程。它不宣称覆盖未读取插件、任意版本或其他未指定 Agent 的全部行为。未提供实际安装版本，因此原生能力均需版本联调后启用。

## 1. 范围与统计

本次登记 **18 个功能域、194 项前端功能与交互要求**。其中通用 95 项、原生条件 95 项、扩展规划 4 项。另对照 **164 项原生目录入口**，每项均有归属或范围说明。

| 范围标记 | 含义 |
| --- | --- |
| 通用 | 本产品应设计的基础交互；仍需后端实现与联调 |
| 原生条件 | 纳入完整前端设计；根据实际版本、会话模式、权限与能力启用 |
| 扩展规划 | 已登记的独立扩展，避免漏项；不自动混入原 MVP |

开发阶段可以排先后，但页面设计时先保留功能归属。主流程中不可用动作隐藏或禁用，能力详情中保留具体不支持原因。不得用“支持某 Agent”替代逐项能力记录。

## 3. 信息架构先确定功能归属

一级导航保留四项：**总览、会话、待处理、我的**。设备与项目从总览进入，设备管理也可从我的进入；同一资源复用同一详情页。审批和普通问题在待处理中分组，通知不自动执行任何操作。

| 页面或交互面 | 主入口 | 承载内容 |
| --- | --- | --- |
| 登录与恢复页 | 启动/登录失效 | 认证、取消、失败与返回原页面 |
| 总览 | 一级导航 | 待处理摘要、设备、最近项目和会话、快速开始 |
| 设备列表与设备详情 | 总览/我的 | 配对、状态、版本、项目、Agent、撤销 |
| 添加设备与绑定确认 | 设备管理 | 扫码、手动码、确认、过期/占用/取消 |
| 项目列表与项目详情 | 设备详情 | 已登记项目、项目内会话与只读文件 |
| Agent 详情与兼容性 | 设备详情 | 可用性、认证状态、版本、能力、配置错误 |
| 会话列表 | 一级导航 | 搜索、筛选、历史和整理 |
| 创建会话页 | 总览/项目/会话 | 设备、项目、Agent、模型、模式、输入 |
| 会话详情 | 会话列表/通知 | 时间线、输入与当前运行控制 |
| 会话设置与更多菜单 | 会话详情 | 模型、模式、命名、目标、整理、历史管理 |
| 分支与历史详情 | 会话更多/消息菜单 | 分支来源、当前分支、恢复、克隆与导出 |
| 输入附件与命令面板 | 会话输入区 | 图片、文件引用、命令、Skills 与待执行消息 |
| 工具和结果详情 | 时间线卡片 | 工具输入摘要、结果、截断、结构化内容 |
| 审批详情 | 待处理/时间线 | 动作、范围、选择、回传与终态 |
| 问题与扩展表单 | 待处理/时间线 | 选择、自由输入、编辑、取消、超时 |
| 计划与任务详情 | 会话详情 | 计划、待办、子任务、后台任务与审查结果 |
| 改动与检查点详情 | 会话详情 | 文件列表、逐行 Diff、来源、还原预览 |
| 文件与成果详情 | 项目/会话结果 | 只读内容、版本、生成文件和下载 |
| 用量与上下文详情 | 会话/Agent 详情 | 统计、限流、上下文、压缩与重试 |
| 扩展详情与诊断 | Agent 详情 | Skills、命令、MCP、插件、hooks 与加载错误 |
| 待处理与通知列表 | 一级导航 | 审批、问题、失败、完成、已处理记录 |
| 我的与偏好设置 | 一级导航 | 账号、设备管理、通知、隐私、帮助 |
| 操作记录与诊断 | 我的 | 配对/审批/取消记录、连接/协议错误 |

这些是产品页面和交互面，不是微信路由配置。可用弹层承载短表单与更多菜单，不要求每个功能新建页面。会话主屏固定保留“状态 + 时间线 + 输入 + 停止当前轮次”；模型、分支、上下文、用量和扩展放到明确的二级入口。

## 5. 状态矩阵：每个按钮都必须有结果归属

| 情况 | 页面必须表达 | 允许的后续操作 |
| --- | --- | --- |
| 未登录/认证失效 | 需要重新登录 | 认证后重取权限，再返回原操作 |
| 初次加载/无数据 | 正在加载与确实为空分开 | 空状态给创建、绑定或返回入口 |
| 手机断网/连接恢复 | 内容是缓存或最后已知状态 | 保留草稿与历史；不假装命令已送达 |
| Node 离线 | 最后已知任务状态及更新时间 | 历史可读；实时命令不静默排队 |
| 运行中 | 当前会话、轮次和任务可确认 | 追加/排队/取消按实际能力显示 |
| 等待审批 | 等待哪一项操作与权限范围 | 仅提交这项原生请求允许的选择 |
| 等待回答 | 具体问题与原生选择约束 | 回答或原生支持的取消；不增加猜测选项 |
| 正在压缩/正在重试 | 真实进行中的阶段 | 显示对应已验证的控制能力 |
| 已提交但未送达 | 用户操作尚未完成 | 查询状态；不重复创建副作用 |
| 原生已接受但仍执行 | 不等同任务完成 | 持续接收真实执行状态 |
| 请求超时/结果未知 | 无法确认是否已执行 | 先对账，不能直接重发 |
| 取消当前轮次 | 先显示正在取消，再显示实际终态 | 已完成文件修改仍可存在 |
| 本轮完成 | 本轮结果已结束 | 可以继续同一会话；不默认关闭会话 |
| 进程关闭/崩溃 | 原进程已不可控 | 检查是否可原生恢复历史 |
| 原生接口不提供/待联调 | 明确不能执行及原因 | 只读展示；能力详情可查原因 |
| 版本不兼容/扩展失败 | 具体组件与错误 | 已知功能继续可用，必要时提示主机处理 |
| 资源撤销/删除/失权 | 该资源不再可访问 | 清除相关缓存并返回可访问列表 |
| 多端已处理/旧轮次 | 当前真实结果 | 禁止把旧操作自动转给新请求 |
| 内容截断/部分失败 | 已展示范围与缺失部分 | 按能力加载详情，不能显示完整成功 |

功能表 G03/G04/G05 对应发送、追加和排队；**G13 取消当前轮次属于会话详情固定主操作**，本表单独规定其状态。停止单个后台任务属于 L07/L09；停止重试属于 O11；关闭底层进程属于 F15。这几种动作分别呈现作用范围和执行结果。

## 7. 本次发现并补齐的缺口

| 既有方案缺口 | 影响 | 本次落位 |
| --- | --- | --- |
| 只强调会话新建/恢复，缺少历史整理入口 | 会话多后无法管理 | F08—F14 |
| 写了分支能力，缺少分支来源和当前分支展示 | 用户无法判断上下文从哪里继续 | F12、F13 |
| 写了运行控制，缺少队列处理和重试控制的区分 | 用户误以为输入立即执行 | G04—G06、O09—O11 |
| 写了用量，缺少上下文、额度和估算标识 | 把余额、Token 和估算混为一谈 | O01—O08 |
| 写了子任务，没有单任务停止入口 | 只能取消整个主任务 | L05—L09 |
| 后端有审计，前端无用户操作记录入口 | 无法追踪审批和撤销结果 | R05 |
| 只有 Agent 就绪示例，缺少未认证/扩展失败状态 | 无法解释为什么不能开始任务 | E02、E06—E09、N11 |
| Skills/MCP 只写加载，缺少目录与诊断入口 | 专属能力被统一聊天界面吞掉 | N01—N12 |
| 只读文件与 Diff 没有明确版本来源 | 旧结果误当成当前文件 | M04、M10 |
| 没有检查点还原的独立语义 | 误认为取消或回退聊天会撤销文件 | M11、M12 |
| 微信账号与 Agent 账号没有分别呈现 | 退出或认证操作作用到错误层 | A04、A05、E06—E08 |
| 高级原生接口没有范围登记 | 后续实现者忘记它们或随意加入主界面 | 第 6、8 节 |

## 9. 全流程遍历清单

| 流程 | 遍历路径 | 结束条件与异常检查 |
| --- | --- | --- |
| 首次使用 | 登录→无设备→添加→确认→无项目引导→选择项目→创建 | 登录取消、配对过期、项目失效都能返回可恢复状态 |
| 新建任务 | 设备→项目→Agent→模型/模式→Prompt→会话 | 不可用 Agent 不创建；重复提交只有一个逻辑任务 |
| 正常多轮 | 输入→流式输出→工具→结果→继续输入 | 保持正确会话，最终正文可回放 |
| 运行中干预 | 运行→追加或排队→原生接受→执行 | 两种输入时机明确；停止当前轮次有真实终态 |
| 人工审批 | 待处理→动作详情→选择→回传→执行 | 超时、请求取消、多端重复与节点离线均可解释 |
| 普通问题 | 待处理→问题表单→回答→原生继续 | 回答不变成新任务，不作用于错误问题 |
| Pi 扩展交互 | 扩展命令→选择/编辑→回答/取消→结果 | 超时和不支持的 TUI 有明确行为 |
| 查看成果 | 结果→Diff→文件→产物下载 | 版本来源、文件删除、内容截断和下载失败都明确 |
| 分支与恢复 | 历史→选择分叉点→新分支→继续 | 来源正确；历史导入与运行进程接管分开 |
| 上下文与重试 | 占用提示→压缩/重试状态→完成或停止 | 不显示伪精确数值，不重复副作用 |
| 子任务处理 | 主会话→任务→详情→停止单项→结果 | 父任务与子任务状态准确，不误停其他任务 |
| 前后台与断网 | 离开→远端继续→回来→认证→快照/补齐→实时 | 未完成消息恢复，无遗漏和重复 |
| Node/网关退出 | 断开→对账→继续或恢复历史 | 不能把新进程冒充旧工具仍在执行 |
| 多设备/多端 | 同时查看多个会话→一端审批→其他端更新 | 设备、项目、会话、轮次不串线 |
| 撤销与失权 | 撤销→连接失效→缓存清理→返回 | 已撤销控制权限不能通过旧页面继续使用 |
| 扩展失效 | MCP/插件加载失败→诊断→重连/主机处理→刷新 | 旧配置与新配置生效状态准确 |

## 10. 页面设计验收门槛

1. 每个纳入项至少有一个页面或组件入口；通用内部能力也有对应状态展示。
2. 每个写操作画出可用、提交中、原生确认、失败、结果未知和过期状态。
3. 每项原生能力记录目标版本、运行模式、来源、映射和联调结果，不按品牌默认开启。
4. 主流程不可用动作与能力详情说明一致，不能一处显示支持、另一处静默失败。
5. 先画通用状态和完整使用流程，再补正常页面；空状态和异常状态属于设计交付。
6. 原型、组件、接口 schema 和验收记录引用本文需求编号；新增或删除功能同步更新来源和范围记录。
7. 本次机械检查只证明“清单内编号唯一、入口不空、原生目录登记完整、引用指向存在的功能”，不等于已经实现、联调或证明所有未知插件都完整兼容。

本轮的输出是功能基线和缺口核对。视觉风格、页面像素、具体路由、组件变量名和协议字段在后续读取项目材料后确定。
